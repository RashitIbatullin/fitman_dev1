# Функциональные требования / Подсистема уведомлений (Notification Service)

*Часть 2 | источник: Требования ТЗ фитнес-тренинг часть 2.docx | [индекс](../INDEX.md)*

Подсистема уведомлений отвечает за своевременную отправку сообщений пользователям через различные каналы связи (Email, SMS, Push) в соответствии с их настройками и бизнес-событиями системы.

#### Архитектура и общие требования

Централизованный сервис: Уведомления должны обрабатываться единым сервисом (отдельным Dart-модулем), который получает события от системы и управляет очередью отправки.

Шаблоны сообщений: Тексты уведомлений должны храниться в базе данных в виде шаблонов с возможностями подстановки переменных (например, {{client_name}}, {{training_time}}). Это позволит администратору изменять тексты без изменения кода.

Очередь отправки (Queue): Для надежности отправка должна использовать очередь сообщений, чтобы избежать потери уведомлений при сбоях в работе внешних сервисов (SMTP, SMS-шлюз).

Логирование: Отправка каждого уведомления должна фиксироваться в отдельной таблице.

#### Типы уведомлений (Бизнес-события)

Система должна отправлять уведомления при наступлении следующих событий:

Приглашение клиента:

Событие: Менеджер нажал "Отправить приглашение" в карточке лида.

Канал: Email или SMS (в зависимости от данных лида).

Получатель: Потенциальный клиент (запись в onboarding_client).

Содержание: Приветствие, уникальная ссылка для активации, инструкция.

Напоминание о занятии:

Событие: За hourNotification часов до начала занятия.

Триггер: Система проверяет расписание каждые 15 минут.

Канал: Push-уведомление в приложении (основной), дублирование на Email (опционально, по настройкам пользователя).

Получатель: Клиент, Тренер, Инструктор (привязанные к занятию).

Содержание: Время занятия, название плана тренировок, ссылка на карточку занятия.

Изменение в расписании:

Событие: Тренер или менеджер изменил время/дату занятия, отменил его.

Канал: Push-уведомление, Email.

Получатель: Клиент, Тренер, Инструктор.

Содержание: Информация об изменении, старое и новое время.

Новое сообщение в чате:

Событие: Пользователь отправил сообщение в чат (Peer-to-Peer или Broadcast).

Канал: Push-уведомление.

Получатель: Участник(и) чата, которые в данный момент не в приложении.

Содержание: Имя отправителя и начало текста сообщения.

Системные уведомления для персонала:

Событие: Поступление новой заявки с сайта (onboarding_client).

Канал: Push-уведомление, Email.

Получатель: Дежурный менеджер.

Содержание: "Поступила новая заявка от [Имя]".

#### Управление подписками (Пользовательские настройки)

Каждый пользователь (в дашборде "Настройки") должен иметь возможность независимо настраивать получение уведомлений:

Общий переключатель: sendNotification (Вкл/Выкл все уведомления).

Время напоминания о занятии: hourNotification (в часах).

Каналы для разных событий: Отдельные переключатели для получения уведомлений по каналам:

Push-уведомления (всегда Вкл, если не выключены на уровне ОС).

Email-уведомления (опционально).

SMS-уведомления (опционально, может быть платной услугой).

#### Технологический стек

```
- **Очередь задач:** Redis Queue или пакет dart_redis
- **Шаблоны сообщений:** PostgreSQL + Handlebars-подобный движок
- **Email отправка:** SMTP сервер (Postfix или внешний провайдер)
- **SMS отправка:** REST API российских SMS-шлюзов
- **Push-уведомления:** Firebase Cloud Messaging (FCM) для мобильных приложений
- **Веб-уведомления:** WebSocket + Service Worker
```
