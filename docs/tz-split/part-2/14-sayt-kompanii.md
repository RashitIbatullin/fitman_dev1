# Функциональные требования / Сайт компании

*Часть 2 | источник: Требования ТЗ фитнес-тренинг часть 2.docx | [индекс](../INDEX.md)*

Сайт компании выполняет две ключевые функции:

- Маркетинговую для привлечение новых клиентов.
- Служит точкой входа в веб-версию приложения для существующих пользователей.
#### Общие требования к дизайну и архитектуре

Стиль: Строгий, лаконичный, корпоративный. Академичный подход с акцентом на надежность и профессионализм. Минимум декоративной графики.

Технологии: Веб-сайт должен быть реализован как Single Page Application (SPA) на Flutter Web, что обеспечит единообразие дизайна и логики с мобильными приложениями.

Адаптивность: Сайт должен корректно отображаться и функционировать на устройствах с разным разрешением экрана (десктоп, планшет, смартфон).

Навигация: Интуитивно понятное главное меню, расположенное в шапке сайта. Меню должно быть доступно на всех страницах.

#### Структура и содержание страниц

Сайт состоит из следующих обязательных страниц:

Главная страница («О компании»):

Краткое описание фитнес-центра, его философия, преимущества.

Блок с ключевыми показателями (количество довольных клиентов, лет на рынке и т.д.).

Призыв к действию (CTA) "Оставить заявку".

Призыв к скачиванию apk мобильной версии на Андроид.

Контакты:

Адрес центра с интерактивной картой (Google Maps/Яндекс.Карты).

Телефон, email, график работы.

Форма для обратной связи (упрощенный аналог блока "Составить заявку").

Расписание работы: Информация о работе центра по дням недели. Данные должны подгружаться из таблицы work_schedules (только для чтения).

FAQ: Страница с ответами на часто задаваемые вопросы.

Отзывы: Модуль для отображения отзывов реальных клиентов.

#### Функциональные блоки

##### Блок «Составить заявку» (Форма лида)

Это ключевой маркетинговый элемент, доступный на главной странице и в виде всплывающего модального окна на других страницах.

Поля формы:

Имя (обязательное, текст).

Пол (обязательное, выпадающий список: Мужской, Женский).

Возраст (обязательное, число).

Телефон (условно-обязательное, валидация формата).

Email (условно-обязательное, валидация формата).

Способ обратной связи (обязательное, радиокнопки: "По телефону", "По email"). Логика: если выбран телефон, обязательным становится поле "Телефон", и наоборот.

Логика работы:

Валидация на стороне клиента: При попытке отправить форму проверяется заполненность обязательных полей и корректность формата. Ошибки выводятся рядом с полями.

Отправка данных: При нажатии кнопки "Отправить" данные формы отправляются методом POST на защищенный (HTTPS) API-эндпоинт бэкенда (например, /api/leads).

Обработка на сервере: Бэкенд создает запись в таблице onboarding_client и запускает процесс уведомления дежурного менеджера (как описано в разделе об онбординге).

Реакция на клиенте: После успешной отправки форма скрывается, а пользователю показывается сообщение: "Спасибо! Ваша заявка принята. Наш менеджер свяжется с вами в ближайшее время.".

##### Блок «Личный кабинет»

Это веб-интерфейс основного приложения, доступный после аутентификации.

Страница входа:

Поля: "Логин (Email/Телефон)" и "Пароль".

Кнопка "Войти".

Ссылка "Забыли пароль?" (запускает стандартный процесс сброса через email).

Функциональность после входа:

После успешной аутентификации пользователь перенаправляется на дашборд, соответствующий его роли (Клиент, Тренер, Менеджер, Администратор).

Функциональность веб-дашбордов на 100% идентична функциональности мобильного приложения, описанной в разделах "Функциональный модуль «Клиент»", «Тренер» и т.д.

Интерфейс должен быть оптимизирован для управления с помощью мыши и клавиатуры, но сохранять общую стилистику мобильного UI.

#### Интеграция с основной системой

API: Веб-сайт общается с бэкендом через те же API и RESTful эндпоинты, что и мобильное приложение.

Аутентификация: Используется единая система аутентификации. Сессия, открытая в браузере, не должна конфликтовать с сессией в мобильном приложении.

Данные: Данные для страниц "Расписание работы" и др. должны браться напрямую из БД основной системы, чтобы избежать дублирования и расхождения информации.

#### Требования к контенту и SEO

Контент: Все тексты на сайте должны быть уникальными, грамотными и отражать специфику центра.

Мета-теги: Настройка title, description и keywords для каждой страницы.

Скорость загрузки: Оптимизация изображений и кода для быстрой загрузки страниц, что критично для SEO и удержания пользователей.
