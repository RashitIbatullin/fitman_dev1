# Функциональные требования / Антропометрия, анализ и рекомендации

*Часть 2 | источник: Требования ТЗ фитнес-тренинг часть 2.docx | [индекс](../INDEX.md)*

Функционал учета и анализа антропометрических данных клиентов, включая постоянные (рост, обхваты для соматотипа) и периодические (вес, обхваты тела) замеры. Формирование рекомендаций по фитнесу, создание промпта для ИИ.

#### Модель данных

- AnthropometryFixed (Постоянные данные)
Хранит базовые, редко изменяемые антропометрические данные клиента, используемые для определения соматотипа и других расчетов.

class AnthropometryFixed {

String? id;

String userId;

DateTime? dateTime;

int? height;

int? wristCirc;

int? ankleCirc;

// ... служебные поля

}

```

- AnthropometryMeasurement (Периодические замеры)
Хранит данные регулярных замеров для отслеживания динамики и прогресса клиента.

class AnthropometryMeasurement {

String id;

String userId;

DateTime dateTime;

double? weight;

int? shouldersCirc;

int? breastCirc;

int? waistCirc;

int? hipsCirc;

double? fatPercentage;

double? muscleMass;

// ... служебные поля

}

```

#### Расчетные и View-модели

- WhtrProfile. Результат расчета соотношения талии к росту (WHtR), содержит сам коэффициент (`ratio`) и его текстовую оценку (`gradation`).
- MetabolicProfile. Результат расчета метаболизма, содержит базовый метаболизм (`bmr`) и суточный расход калорий с учетом активности (`tdee`).
- VisualizationDataPoint. Специализированная модель для экрана визуализации. Содержит как сырые данные замера (вес, обхваты), так и все расчетные (WHtR, BMR, TDEE) для одной точки во времени. Это позволяет фронтенду за один запрос получить все необходимое для построения графиков.
#### API endpoints

Управление антропометрией осуществляется через эндпоинты, разделенные по ролям (клиентские и административные).

GET /api/admin/clients/<id>/anthropometry. (Для админов) Получение списка всех замеров клиента.

POST /api/measurements/visualize. Принимает список ID замеров и возвращает полный набор данных (`List<VisualizationDataPoint>`) для построения всех графиков, включая расчетные.

GET /api/clients/<userId>/measurements/<measurementId>/metabolic-rate. Рассчитывает и возвращает BMR и TDEE для конкретного замера клиента. Использует формулу Кэтча-МакАрдла, которая требует наличия `fatPercentage` в данных замера.

GET /api/dashboard/client/<userId>. Возвращает данные для дашборда конкретного пользователя, включая список последних 7 замеров (`recentMeasurements`) для построения графика прогресса.

Другие эндпоинты для CRUD-операций с замерами, а также для получения расчетных данных (соматотип, WHtR, BMR/TDEE) по одному замеру.

#### Пользовательские интерфейсы

Функционал доступен из дашборда клиента.

##### Антропометрия

(anthropometry_screen.dart)

Главный экран модуля, разделенный на 2 вкладки:

- Вкладка "Замеры. Отображает виджет `AnthropometryListScreen`.
- Вкладка "Постоянные данные. Отображает виджет `FixedValuesView`.
- Кнопка "Создать замер" (+). Видна только сотрудникам на вкладке "Периодические замеры", открывает `anthropometry_edit_screen.dart` для создания новой записи.
##### Постоянные данные

(fixed_values_view.dart)

- Для сотрудников. Форма с редактируемыми полями для роста и обхватов запястья/лодыжки. Кнопка "Сохранить" активна только при наличии изменений.
- Для клиентов. Поля отображаются в режиме "только для чтения", кнопка "Сохранить" скрыта.
##### Список замеров

(anthropometry_list_screen.dart)

Отображает список периодических замеров.

- Чекбокс Выбрать всё. Общий чекбокс колонки, позволяющий выбрать все доступные замеры. Служит для визуализации.
- Чекбокс строки. Каждая строка содержит чекбокс для выбора.
- Меню "Действия". При нажатии на нее открывается выпадающее меню со следующими действиями:
- Сравнение (активно при выборе ровно 2 замеров)
- Анализ (активно при выборе 1 или 2 замеров)
- Визуализация (активно при выборе 1 и более замеров)
- Рекомендации (активно при выборе 1 и более замеров)
##### Сравнение замеров

(comparison_screen.dart)

Экран для визуального сравнения двух замеров.

- Вверху экрана находится легенда с датами и временем замеров.
- Отображает все значения двух замеров.
- Отображается разница значений замеров.
##### Анализ замера

(analysis_screen.dart)

Экран для отображения аналитических данных для одного конкретного замера.

- Виджет "Соматотип". Статичный параметр, рассчитывается на основе постоянных замеров.
- Виджет "Тип фигуры". Динамический параметр, рассчитывается на основе обхватов из выбранного замера.
- Виджет "Индекс WHtR". Динамический параметр, рассчитывается для выбранного замера.
- Виджет "Базовый метаболизм BMR-TDEE". Динамический параметр, рассчитывается для выбранного замера.
##### Анализ двух замеров

(analysis_comparison_screen.dart)

Экран для сравнения аналитических данных двух замеров.

Вверху отображается общая для обоих замеров информация (Соматотип), т.к. она не меняется.

Для каждого изменяемого параметра (Тип фигуры, Индекс WHtR, Базовый метаболизм BMR-TDEE) создается отдельный виджет, где построчно сравниваются значения для первого и второго замера.

##### Визуализация замеров

(anthropometry_visualization_screen.dart)

Экран использует эндпоинт для получения всех необходимых данных за один запрос и отображает подробные графики по выбранным замерам:

- Динамика веса, кг
- Динамика обхватов, см (плечи, грудь, талия, бедра)
- Динамика WHtR (соотношение талии к росту)
- Динамика метаболизма, ккал (BMR и TDEE)
- Состав тела (Жир, % и Мышцы, кг)
##### Система рекомендаций

(system_recommendation_screen.dart)

Система использует детерминированный, основанный на правилах, алгоритм для генерации персональных рекомендаций.

    - Входные параметры для анализа.
Рекомендации строятся на основе комплексных данных клиента:

Профиль пользователя. Цель (`goalTrainingId`), Уровень подготовки (`levelTrainingId`), Пол, Возраст.

Постоянные замеры. Рост, Обхват запястья, Обхват лодыжки.

Данные последнего замера. Обхваты плеч, талии и бедер.

    - Процесс генерации
Алгоритм выполняет несколько шагов:

1.  Расчет промежуточных показателей.

Соматотип. (Эктоморф, Мезоморф, Эндоморф) — определяется по обхватам запястья и лодыжки.

Тип фигуры. (Яблоко, Груша, Песочные часы и др.) — определяется по соотношению обхватов плеч, талии и бедер.

Индекс WHtR. (соотношение талии к росту) и его оценка (Норма, Избыточный вес и т.д.).

2.  Поиск базовой рекомендации. На основе **Типа фигуры**, **Цели** и **Уровня подготовки** система находит соответствующий блок текста в таблице `body_shape_recommendations`.

3. Поиск уточнения. На основе оценки **WHtR** и **Цели** система находит дополнительный блок текста в таблице `whtr_refinements`.

4.  Компоновка и обогащение.

*   Итоговый текст собирается путем сложения базовой рекомендации и уточнения.

*   В начало добавляется объяснение методики расчета (на каких показателях основан вывод).

*   В конец добавляется справочная информация о соматотипе клиента.

    - Виды рекомендаций
Система генерирует два варианта итогового текста:

- Рекомендация для клиента. Упрощенный текст с основными выводами и советами.
- Рекомендация для тренера. Более детальный и технический вариант для профессионального использования.
##### Дашборд клиента

(client_dashboard.dart)

На главный экран клиента добавлен виджет **"Динамика прогресса"**. Это компактный линейный график, который наглядно показывает тренды по двум ключевым показателям:

- Вес (кг)
- Обхват талии (см)
#### Валидация в формах ввода

Для всех полей антропометрии (постоянной и периодической) на экранах `fixed_values_view.dart` и `anthropometry_edit_screen.dart` введена валидация:

1.  Все обязательные поля не могут быть пустыми.

2.  Все обязательные поля не могут содержать значение "0".

3.  Поля биоимпеданса (`fatPercentage`, `muscleMass`) должны быть заполнены **вместе**. Если заполнено одно, второе также становится обязательным. Проверка происходит при нажатии кнопки "Сохранить".

#### Провайдеры данных

Находятся в `frontend/lib/modules/clients/providers/analysis_provider.dart`.

somatotypeStringProvider(userId). Асинхронно получает данные пользователя и постоянные замеры, вызывает **локальный калькулятор** и возвращает строку с соматотипом.

bodyShapeProvider(measurement). Синхронно вызывает **локальный калькулятор** и возвращает строку с типом фигуры для конкретного замера.

whtrProfileProvider(measurement). Асинхронно обращается к whtr, чтобы получить `WhtrProfile` для конкретного замера. Это обеспечивает единство данных с модулем рекомендаций.
