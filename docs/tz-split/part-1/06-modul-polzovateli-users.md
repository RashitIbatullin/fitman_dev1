# Функциональные требования / Модуль "Пользователи" (Users)

*Часть 1 | источник: Требования ТЗ фитнес-тренинг часть 1.docx | [индекс](../INDEX.md)*

Этот модуль инкапсулирует весь функционал, связанный с общим управлением пользователями системы, их аутентификацией, авторизацией на основе ролей и централизованным управлением учетными записями, а также с отображением списков пользователей.

#### Модель данных

Сущность "Пользователь" (User) является базовой для всех участников системы. Модель данных включает:

User. Базовая сущность, содержащая личные данные (ФИО, контакты, дата рождения) и учетные данные для входа (логин, пароль).

Role. Определяет права и обязанности пользователя в системе. Один пользователь может иметь несколько ролей.

user_roles. Связующая таблица для назначения ролей пользователям.

user_settings. Таблица для хранения настроек уведомлений пользователя.

client_profiles, employee_profiles, instructor_profiles, trainer_profiles, manager_profiles, admin_profiles. Дополнительные профили, хранящие данные, специфичные для соответствующей роли пользователя.

competencies. Полиморфная таблица для хранения компетенций пользователей (executor_type = 'user').

// Логическое представление модели пользователя во фронтенде

class User {

final String id;

final String login;

final String? phone;

final String? email;

final String? lastName;

final String? firstName;

final String? middleName;

final int? gender;

final DateTime? dateOfBirth;

final String? photoUrl;

final List<Role> roles;

final UserSettings? settings;

// Дополнительные профили и компетенции могут быть загружены по требованию

User({

required this.id,

required this.login,

this.phone,

this.email,

this.lastName,

this.firstName,

this.middleName,

this.gender,

this.dateOfBirth,

this.photoUrl,

this.roles = const [],

this.settings,

});

}

#### API Endpoints

Взаимодействие с модулем пользователей осуществляется через следующие RESTful API эндпоинты, реализуемые в user_controller.dart:

GET /api/users. Получение списка всех пользователей с возможностью пагинации и фильтрации по ролям, активности, ФИО.

GET /api/users/{id}. Получение детальной информации о конкретном пользователе по его ID.

POST /api/users. Создание нового пользователя. Запрос должен содержать данные для таблиц `users`, `user_roles` и, при необходимости, соответствующих профилей.

PUT /api/users/{id}. Обновление данных существующего пользователя.

DELETE /api/users/{id}. Архивирование пользователя (логическое удаление).

#### Пользовательские интерфейсы

Интерфейс для управления пользователями доступен администраторам и менеджерам и включает следующие экраны:

1. Список пользователей (`user_list_screen.dart`).

Отображение. Пагинированный список или таблица.

Колонки/поля. Фото, ФИО, Роли (в виде чипов), Контакты, Статус активности.

Инструменты.

- Кнопка "Создать пользователя".

- Панель фильтров: по роли, активности, ФИО.

- Поле для поиска по ФИО.

- Переключатель Архив. Переключает отображение архивных-неархивных записей.

Действия в строке. Иконки "Просмотр", "Редактировать", "Архивировать".

2. Карточка просмотра пользователя (`user_detail_screen.dart`).

Назначение. Отображение полной информации о пользователе в режиме "только для чтения", включая его роли, профили (клиента, сотрудника и т.д.) и настройки.

3. Форма создания/редактирования пользователя (`user_edit_screen.dart`).

Назначение. Универсальная форма для создания и редактирования профиля пользователя.

Разделы формы.

Учетные данные. Логин, Пароль (только при создании или сбросе).

Личная информация. ФИО, дата рождения, пол, контакты.

Роли. Группа чекбоксов для назначения/снятия ролей.

Профили. Разделы для редактирования данных специфичных профилей (например, client_profiles, employee_profiles), если пользователь имеет соответствующие роли.
