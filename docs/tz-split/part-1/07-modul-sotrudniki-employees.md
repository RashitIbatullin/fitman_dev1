# Функциональные требования / Модуль "Сотрудники" (Employees)

*Часть 1 | источник: Требования ТЗ фитнес-тренинг часть 1.docx | [индекс](../INDEX.md)*

Этот модуль инкапсулирует весь функционал, связанный с внутренними сотрудниками (инструкторами, тренерами, менеджерами), включая управление их профилями и компетенциями.

#### Модель данных

Модель "Сотрудник" (Employee) является композитной и объединяет данные из нескольких таблиц для предоставления полной информации о тренерах, инструкторах и менеджерах.

User. Базовая сущность, содержащая личные данные (ФИО, контакты, дата рождения) и учетные данные для входа (логин, пароль).

Role. Определяет права и обязанности сотрудника в системе (тренер, инструктор, менеджер). Один сотрудник может иметь несколько ролей.

EmployeeProfile. Общий профиль для всех сотрудников, включающий специализацию, стаж работы и право на обслуживание оборудования.

Профили по ролям (`InstructorProfile`, `TrainerProfile`, `ManagerProfile`). Содержат специфичные для роли атрибуты (например, `can_create_plan` для инструктора).

Компетенции (Competency). Описывает конкретные навыки сотрудника, особенно в контексте технического обслуживания оборудования (например, "Обслуживание кардио-тренажеров").

// Логическое представление модели сотрудника во фронтенде

class Employee extends User {

final EmployeeProfile profile;

final List<Role> roles;

final InstructorProfile? instructorProfile;

final TrainerProfile? trainerProfile;

final ManagerProfile? managerProfile;

final List<Competency> competencies;

Employee({

// ... поля из User

required this.profile,

required this.roles,

this.instructorProfile,

this.trainerProfile,

this.managerProfile,

this.competencies = const [],

});

}

```

#### Таблицы базы данных

Данные о сотрудниках хранятся в наборе связанных таблиц в PostgreSQL:

users. Основная таблица с личной информацией и учетными данными.

roles. Справочник ролей.

user_roles. Связующая таблица для назначения ролей пользователям.

employee_profiles. Профиль сотрудника с общей информацией (стаж, специализация). Связь `One-to-One` с `users`.

instructor_profiles. Дополнительный профиль для инструкторов. Связь `One-to-One` с `users`.

trainer_profiles. Дополнительный профиль для тренеров. Связь `One-to-One` с `users`.

manager_profiles. Дополнительный профиль для менеджеров. Связь `One-to-One` с `users`.

competencies. Полиморфная таблица для хранения компетенций сотрудников (`executor_type = 'user'`).

manager_clients, manager_trainers, manager_instructors, instructor_clients. Таблицы, определяющие иерархические связи и назначения.

#### API Endpoints

Взаимодействие с модулем сотрудников осуществляется через следующие RESTful API эндпоинты, реализуемые в employee_controller.dart:

GET /api/employees. Получение списка всех сотрудников с возможностью пагинации и фильтрации по роли, специализации и ФИО.

GET /api/employees/{id}. Получение детальной информации о конкретном сотруднике по его ID.

POST /api/employees. Создание нового сотрудника. Запрос должен содержать данные для таблиц `users`, `user_roles` и соответствующих профилей.

PUT /api/employees/{id}. Обновление данных существующего сотрудника.

DELETE /api/employees/{id}. Архивирование сотрудника (логическое удаление).

GET /api/employees/{id}/competencies. Получение списка компетенций для конкретного сотрудника.

POST /api/employees/{id}/competencies. Добавление новой компетенции сотруднику.

DELETE /api/employees/{id}/competencies/{competencyId}. Удаление компетенции у сотрудника.

#### Пользовательские интерфейсы

Интерфейс для управления сотрудниками доступен администраторам и менеджерам и включает следующие экраны:

Карточка просмотра сотрудника (`employee_detail_screen.dart`).

Назначение. Отображение полной информации о сотруднике в режиме "только для чтения".

Структура. Используются вкладки (Tabs) для организации информации.

Вкладка "Основное". Личная информация из `users` (ФИО, фото, контакты) и `employee_profiles` (стаж, специализация).

Вкладка "Роли и права". Список назначенных ролей.

Вкладка "Компетенции ТО". Список компетенций по техническому обслуживанию с указанием уровня и статуса верификации.

Вкладка "Назначения". Списки прикрепленных клиентов, инструкторов или тренеров в зависимости от роли.

Форма создания/редактирования сотрудника (`employee_edit_screen.dart`).

Назначение. Универсальная форма для создания и редактирования профиля сотрудника.

Разделы формы.

Учетные данные. Логин, Пароль (только при создании или сбросе).

Личная информация. ФИО, дата рождения, пол, контакты.

Роли. Группа чекбоксов для назначения ролей ('инструктор', 'тренер', 'менеджер').

Профиль сотрудника. Поля "Специализация", "Стаж работы", чекбокс "Может обслуживать оборудование".

Компетенции ТО. Интерактивный список для добавления, редактирования и удаления компетенций.
