# Правила проекта FitMan

Источник по Flutter/Dart: `.cursor/rules/flutter.mdc`.

- Язык ответов и комментариев в коде — русский.
- Стек: Flutter 3.30+/Dart 3.9+, Riverpod; backend Dart Frog/Shelf; общие модели
  `fitman_common`; PostgreSQL (мультитенантность schema-based).

## Продукт: основной функционал (обзор)

FitMan — автоматизация фитнес-центра, веб + мобильные клиенты, единая БД.

1. Расписание — по предпочтениям клиента, доступности залов и оборудования, графику
   тренеров; автосоставление + ручная правка.
2. Калории — расход по упражнениям → занятию → плану; приход и вес вносит клиент,
   расход = BMR + занятие + оборудование.
3. Рекомендации — Core (детерминированные правила, оффлайн) + AI Enhancer
   (опциональный внешний LLM).
4. Форматы — индивидуальные (1+1, гибкий график) и группы (фиксированное расписание);
   общая таблица учёта занятий.
5. Планы — шаблоны отдельно от индивидуальных назначений; прогрессия меняется
   в назначениях, шаблон не трогается.
6. Роли — клиент, инструктор, тренер, менеджер, администратор; ролей может быть несколько.
7. Группы — TrainingGroup (тренер, зал, оборудование, чат, состав вручную) и
   AnalyticGroup (сегменты по финансам, демографии, поведению; могут быть автоматическими).
8. Инфраструктура — залы (вместимость, загрузка, состояние), оборудование (типы +
   экземпляры с инвентарными номерами, бронирование), проверка доступности.
9. ТО оборудования — заявки с фото, внутренние исполнители и внешние подрядчики,
   фото «до/после», история.
10. Онбординг — лиды с сайта/телефона → пригласительные ссылки → активация → знакомство
    с залом и оборудованием.
11. Отчётность — клиенты, сотрудники, инфраструктура, финансы; экспорт PDF/Excel.
12. Оффлайн — фиксация занятий и ввод данных без сети, синхронизация, кэш расписания.
13. Безопасность — RBAC, Row Level Security, аудит действий, защита ПДн.
14. Платформы — iOS/Android + веб, адаптив, единая БД.
15. Развёртывание — без обязательной контейнеризации, данные у заказчика, без BaaS.

## Рабочие правила

- Перед созданием, удалением или переименованием файла — спросить.
- После законченных правок — `dart analyze`.
- Строгая типизация, `dynamic` только при необходимости; `const` где возможно;
  `final` для неизменяемых; композиция вместо наследования.
- Виджеты маленькие, с одной задачей; «бороду» выносить в отдельные функции.
- Riverpod: `Notifier` / `AsyncNotifier`; `ref.watch()` в `build`,
  `ref.read()` в колбэках, `ref.listen()` для навигации, диалогов, SnackBar.
- Модели: `freezed` / `json_serializable`, `copyWith`; `@JsonKey` не нужны
  (настроено в `build.yaml`). После изменения моделей или провайдеров:
  `dart run build_runner build --delete-conflicting-outputs`.
- Ошибки: `try-catch` в провайдерах, корректные `AsyncValue`; логи через
  `logger`, не `print()`.
- Ответ: только изменённые фрагменты; при рефакторинге виджета — класс целиком.
